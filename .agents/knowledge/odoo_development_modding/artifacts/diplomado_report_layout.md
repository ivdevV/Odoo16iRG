# Diplomado report layout notes

Date: 2026-06-15

Module: `addons-extra/extrairg/irg_generacion_diplomados`

## Context

The diplomado PDF is generated by the QWeb template `reports/diplomado_templates.xml` using `web.html_container`, `web.basic_layout`, a custom landscape A4 paperformat, and static image assets under `static/src/img/`.

## Findings

- The wizard and registry keep `diplomado_name` as entered or copied from `op.course.name`; uppercase rendering was caused by CSS in the report template, not by Python logic.
- For QWeb PDF reports, avoid putting the full-page background image behind the page with a negative `z-index`. In wkhtmltopdf this can interact badly with page wrappers and apparent page scaling.
- When report content can grow, do not position independent headings and lists with unrelated absolute `top` values. Use one absolute content region and normal document flow inside it.

## Applied pattern (Full Bleed Layout)

- **Root Structure without standard layouts**: Use `web.html_container` at the root and do **not** use `web.basic_layout` or any default layout. Avoid wrapper divs with the class `article` to prevent Odoo from injecting headers, footers, or margin-generating structures.
- **No `.page` class on pages**: Remove the `.page` class from the top-level divs representing the front and back pages of the diploma (use custom classes like `diploma-page front` and `diploma-page back`). This prevents Odoo's default CSS from applying margins and padding.
- **A4 landscape canvas dimensions**: Use absolute positioning at `width: 297mm; height: 200mm;` (with `10mm` vertical tolerance relative to the `210mm` physical A4 landscape height) to absorb rendering errors or small scaling mismatches of wkhtmltopdf.
- **Canvas Scaling**: Set `transform: scale(1.0);` instead of scaling factors (like `1.08`) to ensure sharp, unskewed vector/image output.
- **Background Image placement**: Place the background image with `inset: 0` and absolute positioning at `width: 100%; height: 100%; object-fit: cover; z-index: 0;`.
- **Vertical position limits**: Place bottom elements (like signatures and logos) at a maximum of `184mm` vertical top value (`top: 184mm;`) to guarantee they remain within the page boundaries.

## Gotchas & Nested Layout issues

- **Double HTML Nesting via `web.basic_layout`**: When using standard layout wrappers in Odoo (like `<t t-call="web.basic_layout">`), Odoo generates an intermediate HTML structure (`<div class="article" ...>`) and adds inline wrappers. In `wkhtmltopdf`, this causes page calculations to fail, leading to whitespace borders and forced page breaks.
- **The page scale overflow**: Scaling the canvas with CSS `transform: scale(...)` to adjust full bleed might cause wkhtmltopdf to detect overflow, rendering empty extra pages. A 1:1 scale (1.0) with slightly reduced canvas height (e.g. `200mm` instead of `209mm` or `210mm`) is the most reliable way to avoid overflow.
- **Bootstrap container constraint overrides**: Standard layouts inject Bootstrap classes that cap the width of wrappers. Always apply a CSS reset to the wrappers in the template:
  ```css
  html, body, body.container, #wrapwrap, main, .article, .page {
      margin: 0 !important;
      padding: 0 !important;
      background-color: transparent !important;
      border: none !important;
      width: 100% !important;
      max-width: none !important;
      min-width: 0 !important;
  }
  ```
