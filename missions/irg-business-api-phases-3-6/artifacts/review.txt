## Architecture

- Service decomposition matches plan: `ElearningService`, `AccessService`, `AcademicService`, `MoodleService`, `GradebookService`, `SurveyService` wired through `api_operation` dispatch tables. No reimplementation of bootstrap, enroll, or Moodle sync — official methods delegated.
- Preview → approve flow preserved; read ops verify immediately; write ops use SAVEPOINT on apply.
- `ALLOWED_ENVIRONMENTS = ('test', 'beta')` keeps production rejected at create time.
- Concurrency: `SELECT FOR UPDATE` on approve plus write_date / content freshness guards on slide and clone paths.

### MENOR

1. **File:** `models/api_operation.py` — `_irg_apply_preview` (L381–386)
   **Issue:** `proposed['datas'] = payload.get('file_b64') or payload.get('datas')` runs for every apply operation, not only `irg_upload_private_attachment`. Likely indentation slip; handlers ignore the extra key today but it pollutes proposed snapshots and could confuse future handlers.
   **Fix:** Indent the `proposed['datas']` assignment inside the `irg_upload_private_attachment` branch (or a dedicated elif).

2. **File:** `tests/` — Moodle mapping apply
   **Issue:** No test exercises `irg_apply_moodle_course_mapping` end-to-end (preview/read covered indirectly; apply path untested).
   **Fix:** Add a post_install test that previews explicit maps, approves, and asserts `irg.moodle.subject.map` rows created/updated without side HTTP (mock or assert local ORM only).

3. **File:** `tests/` — Access sync 30% guard
   **Issue:** `apply_access_reconciliation` implements the official 30% archive ratio guard (L175–183) but no test forces the refusal path.
   **Fix:** Optional follow-up test with controlled snapshot mocks if the official helpers are available in test DB.
